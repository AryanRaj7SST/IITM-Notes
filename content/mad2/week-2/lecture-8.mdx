<TopicSection id="what-is-json" title="1. What is JSON?">

<KeyIdea>
JSON is a text representation of an object that lets us move objects from one place to another.
</KeyIdea>

- JSON stands for JavaScript Object Notation. It is not really a JavaScript concept, but it is very useful for transferring data around (it was also met in MAD 1).
- "Object notation" means we want to transfer an object in some text format from one place to another.
- It began informally as a text-based representation of what a JavaScript object looks like internally, and it was used extensively.
- The notation has now been declared **frozen**. Even if there are complaints (for example, that one notation should have been done differently), the creators will not change it.
- If it ever becomes a real problem, JSON may be replaced with something else. For most use cases it is good enough, and freezing it means your API never changes.

</TopicSection>

---

<TopicSection id="json-api" title="2. The JSON API: stringify and parse">

<KeyIdea>
A global JSON object gives two main methods: stringify (object to string) and parse (string to object).
</KeyIdea>

- In JavaScript, JSON is used through the JSON API.
- The API makes one global namespace object called `JSON` available to your scripts, so you can use `JSON.` plus a method name straight away.
- `JSON.stringify` takes an object and converts it into a string.
- `JSON.parse` takes a string and converts it back, but not directly into your original object. It parses the string into something (a plain object) that can then be used to construct an object.

</TopicSection>

---

<TopicSection id="why-stringify" title="3. Why is it called stringify?">

<KeyIdea>
The aim is a string to send out, not necessarily a file to save.
</KeyIdea>

- The method is not called "write to file" or "write to output" because a JSON string is very often created to be sent directly over a network.
- In that case it may never reach a file on disk.
- So `stringify` focuses only on making the object into a string.

</TopicSection>

<TopicSection id="stringify-demo" title="4. Stringify demo on the Cat example">

<KeyIdea>
Stringifying a Cat gives a clean, standardised, compact string.
</KeyIdea>

The demo reuses the class example: class `Cat` extends `Animal`, its constructor calls `super` (the parent constructor) and sets the sound to meow. A new cat `c` was created and `c.describe()` was logged earlier.

New in this lecture: `JSON.stringify(c)` converts the Cat `c` into a string stored in `p`. Both `c` and `p` are then logged. Other earlier `console.log` lines were removed for clarity.

What the lecture observes in the output:
- The first log is `c.describe()`, giving "tom makes a sound meow". This comes from the `describe` method of Animal.
- Logging `c` shows the name Cat followed by name: tom and sound: meow.
- Logging `p` shows the stringified version. The property names (name, sound), which were raw literals, are now enclosed in quotes. The values tom and meow are enclosed in double quotes.
- Unnecessary white space has been removed. This is not essential, but there is no reason to waste space when the string is only going to another machine or program.

> **Added by tutor:** the exact output of `p` is `{"name":"tom","sound":"meow"}`. See the code section for the reconstructed program.

This gives a clean way to turn an object into a unique string that can be passed around.

</TopicSection>

<TopicSection id="parse-back" title="5. Getting back to an object">

<KeyIdea>
The string has the values but no class information, so parse alone cannot give back a Cat.
</KeyIdea>

- The open question is how to get from the string `p` back to the object. This is not trivial.
- `p` holds only the parameters (name is tom, sound is meow). It does not say whether the object was a dog, a cat or just a dictionary.
- Nothing in the string says there is a class Cat associated with it.
- So to go from the string back to a Cat, we need something in the class `Cat` itself.

</TopicSection>

---

<TopicSection id="from-json" title="6. The static fromJSON method">

<KeyIdea>
A static, class-level method builds a Cat from the parsed object.
</KeyIdea>

- `fromJSON` is a **static** method: a class-level method, not one that exists for each individual object.
- It is invoked directly as `Cat.fromJSON`. You do not need to create a new cat first.
- In the lecture it is given the parsed JSON object, not the string. The speaker notes you could instead pass the string and call `JSON.parse` inside it, but chose to parse first and pass the object.
- It creates a new cat using the object's name and then sets the sound to the object's sound.
- **Design choice:** if you skipped the step of setting the sound from the object, it would still work. The new Cat gets meow from its own constructor anyway (cats can only say meow), and the sound in the JSON string would simply be ignored.
- So how you write `fromJSON` (your JSON interpreter) leaves some choices to you.

Using it in practice:
- Create a variable `cc` and call `Cat.fromJSON` with `JSON.parse(p)` as its input.
- `p` was created by stringifying `c`. Parsing gives just an object (a dictionary), which is fed into the static `fromJSON` of the Cat class.
- The method returns a new Cat, assigned to `cc`.
- Logging `cc.describe()` gives "tom makes a sound meow" again, so the round trip works.

> **Added by tutor:** `JSON.stringify` only includes the object's own data properties. Methods and the class name are not part of the string, which is why the class has to supply the rebuilding logic.

</TopicSection>

<TopicSection id="json-beyond-js" title="7. JSON beyond JavaScript">

<KeyIdea>
JSON has JavaScript roots but is used as a generic format everywhere.
</KeyIdea>

- The name shows its roots in JavaScript, but it is used well beyond JavaScript, including as a generic format for describing various notations.
- It has been successful because it is easy to describe and very natural. With some indentation it is also very easy to read.
- It works very well with JavaScript, so it is a very useful tool for transferring data back and forth between different parts of a system.

</TopicSection>
