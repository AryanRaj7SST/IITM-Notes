<TopicSection id="js-arrays" title="1. Arrays as Generic Collections">

<KeyIdea>
Unlike C arrays, JavaScript arrays are generic, mixed-type collections (similar to Python lists) that can contain numbers, strings, and even functions simultaneously.
</KeyIdea>

In languages like C, an array must be explicitly declared to hold a specific data type (e.g., all `int` or all `char`). In JavaScript, arrays are much closer to Python lists. They are flexible and can hold a mix of data types at the same time.

Arrays in JavaScript are fundamentally objects. If you use the `typeof` operator on an array, it will evaluate to `"object"`. You can easily manipulate an array's size—even creating empty "holes" by artificially setting the `.length` property to a number larger than the current number of elements.

</TopicSection>

<TopicSection id="iterables" title="2. Iterables and Iteration">

<KeyIdea>
An iterable is an object accessed sequentially using a pointer (iterator). Examples include arrays, strings, maps, and the browser DOM tree.
</KeyIdea>

Iteration is the process of going over elements in a collection one by one. For an object to be iterated over, it must be an **iterable**. Single scalar values (like a single number `1` or character `a`) cannot be iterated.

An iterable requires an internal pointer (an iterator) that tracks the current position and dictates how to move to the next element. In JavaScript, iterables extend far beyond arrays:
*   Strings
*   Maps and Sets
*   The Browser Document Object Model (DOM), which is a tree structure that can be sequentially traversed.

</TopicSection>

<TopicSection id="first-class-functions" title="3. First-Class Functions and Callbacks">

<KeyIdea>
JavaScript treats functions as first-class objects, allowing them to be passed as arguments (callbacks) to higher-order functions like map, filter, and find.
</KeyIdea>

JavaScript treats functions as first-class citizens. This means a function is just another object that can be passed as a parameter into another function. 

While this is possible in C using complex function pointers, JavaScript makes the syntax fluid. Higher-order functions like `map`, `filter`, and `find` rely heavily on **callback functions**—functions provided as arguments that execute dynamically depending on the internal logic of the parent function. This enables powerful functional programming patterns and transformation chains.

</TopicSection>

<TopicSection id="modern-collections" title="4. Maps, Sets, and Cleaner Syntax">

<KeyIdea>
Modern JavaScript introduced structures like Map, Set, WeakMap, and WeakSet to provide cleaner, more readable alternatives to old scoping hacks (like IIFEs).
</KeyIdea>

Historically, JavaScript was highly flexible but lacked structured concepts like block scoping or traditional classes. Developers hacked around these limitations using patterns like Immediately Invoked Function Expressions (IIFEs) or complex prototype chains, which were difficult to read.

To solve this, modern JavaScript introduced new collection types (`Map`, `Set`, `WeakMap`, `WeakSet`). While standard JavaScript objects can act like dictionaries, a `Map` provides a cleaner, purpose-built structure for key-value pair collections. 

</TopicSection>

<TopicSection id="destructuring" title="5. Array Destructuring">

<KeyIdea>
Destructuring splits an array or object into multiple distinct variables, enabling Python-like named arguments and default values in JavaScript.
</KeyIdea>

Destructuring is a simple syntactic feature that unwraps values from arrays or objects into separate variables. 

One of its most powerful use cases is simulating named arguments for functions. Instead of passing arguments sequentially by their position (as in C), destructuring allows you to pass an object where variables are matched by name. It also makes setting default values for missing arguments incredibly straightforward.

</TopicSection>

<TopicSection id="generators" title="6. Generators and Cooperative Concurrency">

<KeyIdea>
Generators use the 'yield' keyword to pause execution and return a value without exiting, forming the basis for cooperative concurrency where multiple functions remain active.
</KeyIdea>

A **generator** is an advanced function that can yield multiple values over time. Instead of using `return`—which completely terminates function execution—generators use the `yield` keyword. 

`yield` hands a value back to the caller while saving the exact present state of the function. The function waits to be restarted exactly where it left off. This creates **cooperative concurrency**, allowing two or more functions to pass control back and forth, keeping multiple contexts active simultaneously (a precursor to full parallelism).

</TopicSection>
