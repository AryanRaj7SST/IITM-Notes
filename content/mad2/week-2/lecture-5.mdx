<TopicSection id="modules-idea" title="1. What a Module Is">

<KeyIdea>
A module bundles related functions, objects or values into a file that other code can import for reuse.
</KeyIdea>

- So far the objects seen were arrays, not generic objects. Before objects, the lecture covers how JavaScript encapsulates code in modules.
- Modules matter for reusability: you collect related functions, objects or values together.
- Python analogies: numpy collects numeric functions, scipy is for scientific Python, and there are modules for CSV (comma separated values).
- Many related functions and classes are bundled into one or more files that others import and use.
- In JavaScript, you explicitly export values for other scripts to use and import values from other scripts.

</TopicSection>

---

<TopicSection id="front-vs-back-end" title="2. Front End versus Back End Loading">

<KeyIdea>
Front-end code has to be clear about where packages come from, while back-end code on Node works like Python.
</KeyIdea>

- A lot of JavaScript runs on the front end, so it must be clear how to import: from a local file, from somewhere on the net, downloaded if required, and how packages are addressed relatively.
- JavaScript also runs on the back end using the node.js interpreter. There you can use it like Python: packages, directory hierarchies, and files in directories imported as required.
- Because of these two uses, care is needed about how things are packaged and how code is used.

</TopicSection>

<TopicSection id="module-history" title="3. History: Scripts, CommonJS, AMD, ES6 Modules">

<KeyIdea>
ES6 modules, from ECMAScript 2015, work on servers and browsers with asynchronous loading and are the course's choice.
</KeyIdea>

| Stage | What it is | Notes |
| --- | --- | --- |
| Plain scripts | Scripts included directly in a browser and executed | No notion of modules at the start |
| CommonJS | Server-side modules, once server-side JavaScript began | Uses synchronous loading |
| AMD | Asynchronous module definitions for the browser side | Client-side answer to blocking |
| ES6 modules | ECMAScript 6, formalised in 2015 and developing since | Works on servers and browsers, asynchronous load |

- Synchronous (blocking) loading waits at the import until it completes. That is fine on the server, which imports once and runs.
- On a browser, blocking is unacceptable: it ruins the user experience, and if the server being loaded from is down, the page freezes, since JavaScript works that way (covered later).
- Some packages, and possibly some browsers, do not fully support ES6 modules. Browsers should mostly support it now; some old packages do not.
- The course uses the latest version of the language, not the old one. For older code you may need to learn how modules were written there.

</TopicSection>

<KeyIdea>
npm is the node package manager, and bundlers let Node-style packages be used in the browser; the course ignores this for now.

<KeyIdea>
A script tag needs type module to use import and export, and modules are loaded automatically.

<TopicSection id="named-exports" title="7. Named Exports and the Missing-Export Error">

<KeyIdea>
Only items marked export can be imported; a private function cannot.
</KeyIdea>

- `module1.js` defines `sq(x)`, which squares a value, an exported const `c`, and an exported function `energy` that uses `sq`.
- Both `c` and `energy` are exported, so `import { c, energy }` works and printing each gives a value.
- Importing `sq` too, and printing `sq(10)`, fails: the module does not provide an export named sq, because sq has no export.
- Removing sq from the import lets the code run again.

**File:** `modularity-demo/module1.js`

```javascript
function sq(x) {
  return x * x;
}
export const c = 299792458;
export function energy(m) {
  return m * sq(c);
}
```

**File:** `modularity-demo/modularity.js`

```javascript
import { c, energy } from "./module1.js";
console.log(c);
console.log(energy(1));
```

**What each part does:** `sq` stays private to the module, and lines 2 and 3 print c and the energy for a mass of 1.

**Expected output:**

```text
299792458
89875517873681760
```

**File:** `modularity-demo/modularity.js` (importing sq, fails)

```javascript
import { c, energy, sq } from "./module1.js";
console.log(sq(10));
```

**Expected output:**

```text
SyntaxError: The requested module './module1.js' does not provide an export named 'sq'
```

<TopicSection id="renaming" title="8. Renaming Imports and Exports">

<KeyIdea>
as renames a name on import, or exports an internal name under a different public name.
</KeyIdea>

- On import, `c as speedOfLight` renames it, and the new name is used from then on (for internal use).
- On export, write the module with internal names `speedOfLight` and `e`, then `export { speedOfLight as c, e as energy }`.
- The importer still writes `import { c, energy }` and it works as before: internally the value is speedOfLight, but it is exported as c.

**File:** `modularity-demo/modularity.js` (rename on import)

```javascript
import { c as speedOfLight, energy } from "./module1.js";
console.log(speedOfLight);
console.log(energy(1));
```

**Expected output:**

```text
299792458
89875517873681760
```

**File:** `modularity-demo/module1.js` (rename on export)

```javascript
const speedOfLight = 299792458;
function e(m) {
  return m * speedOfLight * speedOfLight;
}
export { speedOfLight as c, e as energy };
```

**What each part does:** line 5 exports the two internal names under the public names c and energy, so the earlier `modularity.js` runs unchanged.

[check: the body of e is not stated by the lecturer.]

</TopicSection>

<TopicSection id="default-export" title="9. Default Export">

<KeyIdea>
Using export default exports one item, and the importer chooses its name, without braces.
</KeyIdea>

- In `module1.js`, a value is declared but not exported, and an unnamed function is exported with `export default function`. Normally it would be named, like `function energy(m)`.
- The module exports only a single thing, here a function.
- `import c, energy` no longer works since they are not exported.
- `import energy from "./module1.js"` takes the default export and gives it the name energy, and calling it gives the expected value.

**File:** `modularity-demo/module1.js`

```javascript
const c = 299792458;
export default function (m) {
  return m * c * c;
}
```

**File:** `modularity-demo/modularity.js`

```javascript
import energy from "./module1.js";
console.log(energy(1));
```

**What each part does:** c stays private, the unnamed function is the default export, and line 1 imports it with the name energy.

**Expected output:**

```text
89875517873681760
```

</TopicSection>

<TopicSection id="read-only-imports" title="10. Imported Variables Are Read-Only">

<KeyIdea>
An importer cannot assign to an imported variable, but an exported function in the module can change it.
</KeyIdea>

- The module exports a value x declared with let (not const) and a function incx that modifies x.
- The importer imports x and incx, and logging x gives the default value 0.
- Trying to change x directly (for example with x plus plus) gives assignment to constant variable. Even though x is let in the module, importers get only a read-only view of exported variables.
- Calling `incx()` works: x becomes 1.
- So the only way to change an imported value is to call functions written in the same scope as the exported value. This gives a value that changes over time but cannot be directly modified.

**File:** `modularity-demo/module1.js`

```javascript
export let x = 0;
export function incx() {
  x += 1;
}
```

**File:** `modularity-demo/modularity.js` (direct change, fails)

```javascript
import { x, incx } from "./module1.js";
console.log(x);
x++;
```

**Expected output:**

```text
0
TypeError: Assignment to constant variable.
```

**File:** `modularity-demo/modularity.js` (through the function)

```javascript
import { x, incx } from "./module1.js";
console.log(x);
incx();
console.log(x);
```

**What each part does:** line 3 calls the module's function, and line 4 shows the changed value.

**Expected output:**

```text
0
1
```

</TopicSection>

<TopicSection id="objects-overview" title="12. Objects in JavaScript">

<KeyIdea>
Everything in JavaScript is an object, and objects have literals, methods, this and standard methods.
</KeyIdea>

- Object literals assign values to named parameters in an object.
- Object methods are functions that can be called on the object.
- The special variable `this` is found inside objects (covered below).
- Call, apply and bind are functions of functions, interesting to know.
- The parent class Object has standard methods: keys, values, entries and so on. An object can be used as a dictionary, and these methods iterate through its values.

</TopicSection>

<TopicSection id="prototypes-and-classes" title="13. Prototype-Based Inheritance and Classes">

<KeyIdea>
JavaScript objects inherit through prototypes with single inheritance, and the class keyword is a cleaner syntax on top.
</KeyIdea>

- Object orientation exists but not as in Java or Python. The `class` keyword now exists and should be used, as it makes code cleaner.
- Underneath it works with prototypes: instead of one object inheriting from another, create two objects and set the prototype of one to the other, so it automatically gets the behaviour of the parent object.
- There is a single inheritance track: always one direct parent, unlike multiple inheritance in other languages.
- Multiple inheritance should be used with caution anyway, so this is not a showstopper. Often you can do without it, and prototype-based inheritance is quite powerful.
- A class is a better syntax. Constructors must explicitly call the parent constructor. Mixins or multiple inheritance can be implemented but are complicated and are not covered.

</TopicSection>

<TopicSection id="methods-and-this" title="14. Methods and this">

<KeyIdea>
A function stored on an object is a method, and this refers to the object itself.
</KeyIdea>

- Start with a basic object and print it. A function can be added as an element: `xx.add = function...`.
- `typeof xx` is object, `typeof xx.add` is function, and `xx.add(3, 4)` gives 7. So add is a method of this object; there are no classes yet.
- `xx.f` is an anonymous function of x returning `this.a + x`. `this` refers to the object, like self in Python or this in Java, and `this.a` is 5, so `f(10)` gives 15.
- Writing just `a + x` does not work, because there is no variable a in that scope.

**File:** `modularity-demo/objects.js`

```javascript
let xx = { a: 5 };
console.log(xx);
xx.add = function (x, y) {
  return x + y;
};
console.log(typeof xx);
console.log(typeof xx.add);
console.log(xx.add(3, 4));
xx.f = function (x) {
  return this.a + x;
};
console.log(xx.f(10));
```

**What each part does:** lines 3 to 5 add a method, lines 6 to 8 show its type and result, and lines 9 to 12 use this.a.

**Expected output:**

```text
{ a: 5 }
object
function
7
15
```

**Without this (fails):**

```javascript
xx.g = function (x) {
  return a + x;
};
console.log(xx.g(10));
```

**Expected output:**

```text
ReferenceError: a is not defined
```

[check: the file name and the exact object literal are not stated; I used objects.js and a equal to 5, inferred from this.a being 5.]

</TopicSection>

<TopicSection id="copying-objects" title="15. Copying Objects">

<KeyIdea>
Assigning an object copies only a reference; spreading copies the values, but only one level deep.
</KeyIdea>

- With `y = x`, printing both gives the same value. After setting `x.a` to a new value, both x and y show the change: y is just a pointer (reference) to x.
- To copy, use the spread operator: `z = { ...x }` spreads the values out into individual copies.
- After changing `x.a` again to 5, x and y show 5 but z still shows 3.
- Shallow versus deep copying: if there are further objects inside the object, spreading does not copy them individually.
- Helper functions can make complete copies. Plain assignment is not enough for a copy.

**File:** `modularity-demo/objects.js`

```javascript
let x = { a: 1, b: 2 };
let y = x;
console.log(x, y);
x.a = 3;
console.log(x, y);
let z = { ...x };
x.a = 5;
```
