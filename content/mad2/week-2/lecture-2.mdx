<TopicSection id="eval" title="4. Evaluating Strings with eval">

<KeyIdea>
eval evaluates an expression given as a string at run time and returns the result.
</KeyIdea>

- Shown in the browser console: `eval("3 * 5")` gives 15, and `eval("3 * 5 + 2")` gives 17.
- It respects operator order, so the page does not have to handle that.
- It is not very safe, but it works for this example. MDN docs describe it.

<TopicSection id="read-write-value" title="6. Reading and Writing the Text Box">

<KeyIdea>
document.getElementById returns an element whose value attribute can be read and then set to the answer.
</KeyIdea>

- Get the element by its id (here `expression`) and read the value attribute.
- First check with `console.log` that the value arrives: entering `3 + 6` logs it.
- Compute the answer with `eval` and set it back into the same text box, so 3 + 6 becomes 9.
- Typing `6 * 7` gives 42, and `4 / 2 + 3` gives 5.

**File:** `calculator/index.html` (fragment)

```javascript
function calculate() {
  const expression = document.getElementById("expression").value;
  console.log(expression);
  const answer = eval(expression);
  document.getElementById("expression").value = answer;
}
```

**What each part does:** line 2 reads the box, line 3 checks it in the console, line 4 evaluates it, and line 5 writes the answer back.

**Expected output:** `5 * 6` becomes 30 in the box. (Tested: 5 * 6 gives 30, 3 * 5 + 2 gives 17, 4 / 2 + 3 gives 5.)

</TopicSection>

<TopicSection id="validation-try-catch" title="7. Validation and try-catch">

<KeyIdea>
Run the evaluation only when the box has a value, and wrap it in try and catch so errors are handled.
</KeyIdea>

- With an empty box, clicking prints undefined, because the value is undefined.
- Add a check so the work is done only if there is a valid value; otherwise nothing happens.
- A bad expression throws an exception, so add a try and catch block.
- First the catch block just logs `bad expression` to the console.
- Test by entering a bad expression.

**File:** `calculator/index.html` (fragment)

```javascript
function calculate() {
  const expression = document.getElementById("expression").value;
  if (expression) {
    try {
      const answer = eval(expression);
      document.getElementById("expression").value = answer;
    } catch (e) {
      console.log("bad expression");
    }
  }
}
```

**What each part does:** line 3 skips empty input, lines 4 to 6 try the evaluation, and lines 7 to 9 handle errors.

**Expected output:** a bad expression such as `3 +` leaves the box unchanged and prints `bad expression` in the console.

</TopicSection>

<TopicSection id="dom-log" title="8. Logging Results by Creating DOM Nodes">

<KeyIdea>
createElement and createTextNode build list items at run time, and appendChild attaches them to the page.
</KeyIdea>

- Show all evaluated expressions and errors at the bottom, in a div with a list that keeps growing.
- Put this work in a separate function, `addLog(message)`, because functions should be small and purposeful.
- Steps: get the list by id `log` (variable `ul`); create an `li` with `document.createElement`; create the message with `document.createTextNode`; append the text to the `li`; append the `li` to the list.
- `createElement` takes the tag name, so any tag can be created dynamically.
- On a bad expression, the log gets a message such as the expression is bad, please fix it. On success it logs the expression and answer.
- An h3 with the word Log is added to make the list more visible.
- Examples: 3 + 5, then 6 * 7 and a division each add to the list; an error adds the message.

**File:** `calculator/index.html` (fragments)

```html
<div>
  <h3>Log</h3>
  <ul id="log"></ul>
</div>
```

```javascript
function addLog(message) {
  const ul = document.getElementById("log");
  const li = document.createElement("li");
  const messageTextNode = document.createTextNode(message);
  li.appendChild(messageTextNode);
  ul.appendChild(li);
}
```

**What each part does:** line 2 finds the list, line 3 creates the item, line 4 creates the text, line 5 puts the text in the item, and line 6 puts the item in the list.

[check: the lecturer says ordered list but names it ul and says slash ul; I used ul. The success message is spoken as expression equal to answer; I used expression = answer.]

</TopicSection>

<TopicSection id="mathjs" title="9. Scientific Functions with math.js">

<KeyIdea>
Include math.js and call math.evaluate instead of eval to get scientific functions.
</KeyIdea>

- Go further with a math library, math.js, and call its evaluate function, which also supports scientific functions.
- Download it or load it from a CDN (the lecturer uses jsDelivr) with a script tag with a src.
- Copy the existing function without modifying it, name it `mathCalculate`, and replace `eval` with `math.evaluate`.
- Now `sin 90` style input gives scientific answers.

**File:** `calculator/index.html` (fragment)

```javascript
function mathCalculate() {
  const expression = document.getElementById("expression").value;
  if (expression) {
    try {
      const answer = math.evaluate(expression);
      document.getElementById("expression").value = answer;
      addLog(expression + " = " + answer);
    } catch (e) {
      console.log("bad expression");
      addLog(expression + " is bad, please fix it");
    }
  }
}
```

**What each part does:** line 5 is the only change from `calculate`, using `math.evaluate`.

**Expected output:** `3 * 5` gives 15, and `sin(90)` gives 0.8939966636005579 (tested with math.js 12.4.2).

> **Added by tutor:** math.js uses radians by default, so `sin(90)` is not 1. Writing `sin(90 deg)` gives 1 (tested).

</TopicSection>

<TopicSection id="event-listener-onload" title="10. addEventListener and onload">

<KeyIdea>
Attach the click handler from JavaScript in an initialize function that runs when the body has loaded.
</KeyIdea>

- Events need not be attached in the HTML. To centralise them, create a function `initializeApp`, keeping the HTML plain with no JavaScript.
- Inside it, get the button by id `calculate`. The variable is named `calculateButton` to avoid confusion with the function of similar name.
- Call `addEventListener` with the event name `click` and the function to call, here `mathCalculate`.
- The function is passed as a value, because functions are first-class and can be passed around.
- The first attempt used the wrong method name; the correct one is `addEventListener`. Many listeners can be added to the same button.
- `initializeApp` must run on load. First it was called at the end of the script after the DOM loaded. Better is the body `onload` event, which fires once the body has loaded fully, and the `onclick` attribute is removed.
- After this, `3 * 5` gives 15 and `sin(90)` works.

**File:** `calculator/index.html` (fragments)

```html
<body onload="initializeApp()">
```

```javascript
function initializeApp() {
  const calculateButton = document.getElementById("calculate");
  calculateButton.addEventListener("click", mathCalculate);
}
```

**What each part does:** line 2 gets the button, and line 3 attaches `mathCalculate` as the click handler.

> **Added by tutor:** `mathCalculate` is passed without parentheses, so the function itself is handed over rather than called. In my final file the older `calculate` function remains but is no longer attached to the button.

</TopicSection>
