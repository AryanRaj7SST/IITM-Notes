<TopicSection id="router-setup" title="1. Configuring Vue Router and Route Records">

<KeyIdea>
Vue Router synchronizes browser navigation with component rendering via the `<RouterLink>` navigation element and the `<RouterView>` viewport container.
</KeyIdea>

In modern Vue applications, the router is created and registered in `main.js`:

```javascript
import { createApp } from 'vue';
import App from './App.vue';
import router from './router';

const app = createApp(App);
app.use(router);
app.mount('#app');
```

In your root template (`App.vue`), place `<RouterLink>` for navigation anchors and `<RouterView>` where matching views should mount:

```html
<nav>
  <RouterLink to="/">Home</RouterLink>
  <RouterLink to="/courses">Courses</RouterLink>
</nav>
<main>
  <RouterView />
</main>
```

Vue Router automatically applies active CSS classes (`router-link-active`) to links matching the current route.

</TopicSection>

<TopicSection id="dynamic-params" title="2. Dynamic Route Matching and Route Parameters">

<KeyIdea>
Dynamic segments marked with a colon (`:`) match variable path segments, making it easy to display dynamic resources from a single template.
</KeyIdea>

```javascript
// Route definition
{ path: '/students/:rollNo', component: StudentProfile, props: true }
```

When a user visits `/students/21F1000123`, the component receives `rollNo="21F1000123"` directly as a prop:

```html
<script setup>
const props = defineProps({
  rollNo: String
});
</script>

<template>
  <h2>Profile for Student: {{ rollNo }}</h2>
</template>
```

Using `props: true` ensures the component remains modular and independent of routing implementation details.

</TopicSection>

<TopicSection id="nested-routes" title="3. Nested Routes and Component Hierarchies">

<KeyIdea>
Nested routes model nested user interfaces where parent shells (like sidebars and tabs) persist while interior content swaps dynamically.
</KeyIdea>

Nested routes are declared using the `children` array:

```javascript
const routes = [
  {
    path: '/dashboard',
    component: DashboardLayout,
    children: [
      { path: '', component: DashboardOverview }, // default child
      { path: 'grades', component: DashboardGrades },
      { path: 'settings', component: DashboardSettings }
    ]
  }
];
```

When navigating to `/dashboard/grades`, `DashboardLayout` renders its outer shell, and `DashboardGrades` renders inside the `<RouterView>` located inside `DashboardLayout`.

</TopicSection>

<TopicSection id="navigation-guards" title="4. Navigation Guards and Route Authentication">

<KeyIdea>
Navigation guards intercept route transitions, allowing developers to enforce authentication, verify permissions, and fetch critical data before views load.
</KeyIdea>

Vue Router provides guards at three levels:
1. **Global Guards**: `router.beforeEach()` executes on every single route transition across the entire app.
2. **Per-Route Guards**: `beforeEnter: (to, from) => { ... }` defined directly on specific route records.
3. **In-Component Guards**: `onBeforeRouteLeave` and `onBeforeRouteUpdate` hooks inside component `<script setup>`.

```javascript
// Modern Vue Router 4 returning boolean or route location
router.beforeEach(async (to) => {
  const isAuth = checkLoginToken();
  if (to.meta.requiresAuth && !isAuth) {
    return { name: 'login' }; // Cancels and redirects
  }
});
```

Using `meta` fields is the standard way to declare metadata like required permissions, page titles, or breadcrumbs.

</TopicSection>
