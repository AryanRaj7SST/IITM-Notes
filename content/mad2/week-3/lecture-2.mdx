<TopicSection id="setup" title="1. Setup: editor, browser and Vue Devtools">

<KeyIdea>
You need an editor, Firefox or Chrome, and the Vue Devtools add-on, which adds a Vue tab to the developer tools.
</KeyIdea>

- Goal: set up and run a Hello World Vue application, as an introduction to the basics of Vue.
- You need an editor (VSCodium, Sublime Text or Gedit; the speaker uses Sublime Text), a browser (Firefox or Chrome) and Vue Devtools.
- Vue is a JavaScript framework. **Vue Devtools** is a Chrome or Firefox add-on used for debugging throughout the course.
- Install it from devtools.vuejs.org using the Google Chrome extension or the Firefox extension link. It then shows under extensions and themes in the browser settings.
- To check it is enabled, right click on any page, choose Inspect, and look for the **Vue** tab in the developer tools. The speaker also runs it in a private window.

</TopicSection>

<TopicSection id="hello-page" title="2. A plain Hello World page">

<KeyIdea>
Start with a simple HTML page and move the app code into a separate application.js file.
</KeyIdea>

- Create a simple HTML file (`application.html`), give it the title Hello world and add a div with the text Hello world. Open it locally and refresh to see it.
- Add a second file `application.js` where all the application code will go.
- Include it with a `script` tag (`src="application.js"`) at the bottom of the page, so it loads once the whole page is loaded. This is just including a JavaScript file in the HTML.

</TopicSection>

<TopicSection id="why-vue" title="3. Plain JavaScript vs Vue, and which Vue">

<KeyIdea>
Setting innerHTML by hand does not scale to a full app, so we use Vue 2 (development build while learning).
</KeyIdea>

- Suppose the message should live in JavaScript and be displayed in the div. One option: give the div an id (`app`) and use `document.getElementById('app').innerHTML` set to the message.
- This is a very rudimentary way and very limited. It is fine for one simple message, but if the whole application lives inside the app div it becomes unmanageable. That is where Vue.js comes in.
- There are two versions, Vue 2 and Vue 3. Vue 2 is the most used currently and is the one used in this course (with small changes Vue 3 could be used too).
- Include Vue from its Get started page. The **development version** has more logs and console logs, so debugging is easier. For production use the minimised, optimised version. The speaker copies the development script tag into the page.

</TopicSection>

<TopicSection id="vue-instance" title="4. The Vue instance: el, data and an expression">

<KeyIdea>
A Vue instance attaches to an element with el, holds its values in data, and the HTML shows them with an expression.
</KeyIdea>

- Create the app by instantiating the Vue class: an app called `app` created with `new Vue`.
- Vue takes parameters; the two most important are:
  - `el` (element): the id of our app, written `#app`.
  - `data`: the data used in the app. Here `message` with the value Hello world, moved out of the HTML.
- Loading the page now still shows nothing. Although `el` is tied to the div, the HTML has not been told to use this attribute.
- Add an **expression** in the HTML (similar to a template): the message in double curly brackets. The id app is attached to the Vue instance through `el`, and the expression takes its value from the `message` attribute in `data`. Now Hello world shows.

</TopicSection>

<TopicSection id="reactivity" title="5. Vue Devtools and reactivity">

<KeyIdea>
Change a data value and the page updates by itself; you never touch the UI.
</KeyIdea>

- Inspect the page and open the Vue tab: it shows the root element, an instance of the Vue class associated with our div, with its data and `message` Hello world.
- In the console `app` is available. Setting `app.message` to Hello Thej changes the value on the page and in the Vue tab at once.
- You can also edit the value in the Vue tab (the speaker types Hari and saves) and the page changes. Devtools gives direct access to components, attributes, events and so on.
- This is **reactivity**. Vue looks at the values, and as soon as the value of `message` changes it reacts and updates the page, instantly.
- Refreshing returns to the original message. You only update the data and the UI follows; no change to the UI is needed. This is the most important part of using Vue.

</TopicSection>

<TopicSection id="events" title="6. Events: v-on and methods">

<KeyIdea>
v-on plus an event name (such as click) calls a function defined under methods on the Vue object.
</KeyIdea>

- Put the message in a `p` tag (it still works) and write it as Hello World. Add a standard `button` labelled Say hi. At first, clicking it does nothing.
- To act on an event we need an **event handler**. Normally one writes onclick (as in the previous session); in Vue, use `v-on`, followed by the event name to handle, here `click`, and the handler name (`say_hi`).
- Refreshing and clicking throws an error, because `say_hi` is not defined yet.
- Like `data`, the Vue object can have a `methods` attribute. Define the first method `say_hi` as an anonymous function.
- Inside it, set the message to hi using `this.message`. `this` is used because the message belongs to the same object. Now clicking gives hi.
- What we learned: add a button, attach a handler with `v-on` and `click`, and implement it in the `methods` of the root Vue object. There can be many methods in one Vue object, called from various places.
- Other events exist too, such as mouse over, which could be added and handled in the same way.

</TopicSection>

<KeyIdea>
Add a count value to data, increase it inside the method and show it in the page.

- The lecture calls this part "attribute binding" (making the messaging easier) [check: what is shown is displaying a data value in the page, not binding an HTML attribute].

- We simply added another attribute, count, incremented it and referred to it in the page.

<TopicSection id="conditionals" title="8. Conditionals: v-if, v-else-if and v-else">

<KeyIdea>
Show different elements depending on the value of an attribute.
</KeyIdea>

- Goal: show "No replies yet" when the count is 0, and the number of replies when it is more than 0. With two `p` tags and no condition, both show.
- Vue has conditionals based on attributes: `v-if` with the condition (count equal to 0) on the first, and `v-else` (spelled e-l-s-e) on the second.
- Now it shows No replies yet; after Say hi it shows the new text. While count was 0 the first was used, and once it passed 0 the second was used.
- For fun add another condition with `v-else-if`: when the count is above a threshold show "You are very popular"; until then show the number of replies. The speaker first tries 5, and later uses 3 for the demo [check: threshold spoken as 5, then "greater than two ... make it three"].
- In the demo: No replies yet, then hi, hi, hi, and once the threshold is passed, You are very popular. This is how conditional statements are used in Vue.

<TopicSection id="v-model" title="9. Taking input with v-model (two-way binding)">

<KeyIdea>
v-model binds an input and a data value in both directions.
</KeyIdea>

- Goal: find out who is saying hi. Add an `input` of type text with the placeholder Your name.
- Typing a name and clicking Say hi does nothing with the name yet.
- Until now there was **one-way binding**: when data changed, the HTML changed. There was no binding from the HTML into data.
- That is done with `v-model`, which binds the other way, i.e. **two-way binding**. Bind the input to `visitor_name` and add it to `data`, empty by default.
- Check in Devtools: after typing Rajesh and clicking, the value of `visitor_name` (checked through `app` in the console and the Vue tab) is Rajesh.
- The speaker also shows the visitor name in the page (a "who said hi to you" p tag showing Rajesh said hi), then removes it later.

</TopicSection>

<TopicSection id="visitors" title="10. Storing visitors in an array">

<KeyIdea>
Push each name into a visitors array and clear the input so the user sees it was used.
</KeyIdea>

- We do not want the name to show as soon as it is typed; we want it to count when Say hi is clicked.
- Add another data variable `visitors`, an array. In `say_hi`, `this.visitors.push(this.visitor_name)` adds the name to the array.
- Test: Raj, Thej and Krishna each say hi. In the Vue tab, root shows the visitors array containing all three names, and `visitor_name` shows the latest, Krishna.
- Clear the input after each click by setting `this.visitor_name` back to empty, so people know it was used.
- **Bug:** the first attempt did not clear because the speaker typed a comma instead of a dot (`this.visitor_name` needs the dot). After the fix, the input clears after each click, while the array in the Vue tab still holds every name (Raj, Thej, Abdul, then Fatima).
- Now there are three replies and their names are captured; the next step is to show the names.

</TopicSection>

<TopicSection id="loops" title="11. Looping with v-for">

<KeyIdea>
v-for repeats an element once for each item in an array.
</KeyIdea>

- Create an unordered list (`ul`). We want as many `li` items as there are names in `visitors`.
- On the `li`, add `v-for` with `name in visitors`. It loops over `visitors` and each name appears in `name`, one by one. Print `name` inside the `li` with an expression.
- In the demo each name is added below the list as it is added to `visitors`, e.g. Rajat, Rani, Maya, Rajesh. Adding Fatima shows her in the list and also moves the message to You are very popular.
- Removing a name from the data by another route (Devtools) removes it from the list too. The count does not follow, because `count` is a separate value incremented on each click [check: the speech here is unclear ("this will not run, so that is how it is two-way"); this is my reading].

</TopicSection>

<TopicSection id="computed" title="12. Computed properties">

<KeyIdea>
A computed attribute is calculated from other data (here the length of visitors), so values never go out of sync.
</KeyIdea>

- To make the message follow the names, do not depend on a separately kept count. Take the count from `visitors` instead, so that you do not depend on one and not on the other.
- Remove `count` from `data` (and the increment) and declare `count` under **computed**, as a function that returns the length of the array: `this.visitors.length`. The attribute is computed and not stored, so both are in sync.
- First try: the replies showed the wrong value. There was a spelling mistake in `length`, which the speaker fixed. The speaker also changed the threshold (set to three).
- Test: Raj, Thej, Rahim, Shweta. The page now follows the computed count and not a count we keep ourselves.
- Computed attributes are very useful when the value of an attribute depends on multiple other attributes; many calculations can be done in them.

</TopicSection>
