<TopicSection id="sfc-architecture" title="1. Anatomy of a Single File Component (.vue)">

<KeyIdea>
Single File Components (SFCs) encapsulate the Three Pillars of Web Development (Template, Script, Style) in a unified, syntax-highlighted unit.
</KeyIdea>

An SFC file consists of three top-level language blocks:

1. `<template>`: Contains the HTML structure and Vue directives.
2. `<script setup>`: The modern Composition API entry point containing reactive state, imports, and functions.
3. `<style>`: CSS styling for the component (optional `scoped` attribute).

The `@vitejs/plugin-vue` compiler parses the `.vue` file at build time, compiling the template into an optimized JavaScript render function.

</TopicSection>

<TopicSection id="scoped-css" title="2. Scoped CSS and Style Encapsulation">

<KeyIdea>
Scoped CSS eliminates global stylesheet collisions, allowing components to use simple, readable class names like `.title` without fear of naming clashes.
</KeyIdea>

When `<style scoped>` is used:

```html
<style scoped>
.header {
  color: #0284c7;
}
</style>
```

PostCSS automatically compiles this into:

```css
.header[data-v-f3f3eg9] {
  color: #0284c7;
}
```

If you need a scoped style to penetrate into a child component or third-party library, use the deep selector `:deep(.child-class)`.

</TopicSection>

<TopicSection id="vite-vs-webpack" title="3. Vite vs Webpack: Unbundled Native ES Modules">

<KeyIdea>
Vite revolutionized frontend tooling by utilizing native ES modules supported by all modern browsers, shifting bundling from the developer server to the browser's on-demand request lifecycle.
</KeyIdea>

| Dimension | Webpack Dev Server | Vite Dev Server |
| :--- | :--- | :--- |
| **Server Startup** | Slow; bundles entire project before booting | Instant (under 300ms); serves unbundled ESM |
| **HMR Speed** | Degrades as project grows larger | Constant $O(1)$ time regardless of app size |
| **Pre-bundling** | Done via Node.js Babel | Done via Go-based `esbuild` (10-100x faster) |
| **Production Build** | Webpack production pipeline | Rollup with advanced tree-shaking |

</TopicSection>

<TopicSection id="hmr-and-build" title="4. Hot Module Replacement (HMR) and Production Builds">

<KeyIdea>
HMR allows developers to tweak user interface styling and component templates with sub-second feedback in the browser while preserving ongoing reactive state.
</KeyIdea>

During development:
- When you edit a `.vue` file, Vite transmits an update message across a WebSocket.
- The browser fetches only the edited component module.
- Vue's Virtual DOM swaps the component in place without resetting counters or active tab selection.

When building for production:
```bash
npm run build
```
Vite outputs minified, hash-versioned assets into `/dist` with dead code eliminated (tree-shaking), ready for CDN distribution.

</TopicSection>
