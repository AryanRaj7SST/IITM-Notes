      from fastapi import APIRouter, HTTPException, status
      from pydantic import BaseModel, Field
      from typing import List

      router = APIRouter(prefix="/api/v1/courses", tags=["courses"])

      class CourseSchema(BaseModel):
          code: str = Field(..., example="mad2")
          title: str = Field(..., min_length=5, max_length=100)
          credits: int = Field(default=4, ge=1, le=8)

      # In-memory database
      COURSES_DB = {
          "mad2": {"code": "mad2", "title": "Modern App Dev 2", "credits": 4}
      }

      @router.get("", response_model=List[CourseSchema], status_code=status.HTTP_200_OK)
      def list_courses():
          return list(COURSES_DB.values())

      @router.get("/{code}", response_model=CourseSchema)
      def get_course(code: str):
          course = COURSES_DB.get(code.lower())
          if not course:
            raise HTTPException(
                status_code=status.HTTP_404_NOT_FOUND,
                detail=f"Course '{code}' not found."
            )
          return course

      @router.post("", response_model=CourseSchema, status_code=status.HTTP_201_CREATED)
      def create_course(payload: CourseSchema):
          key = payload.code.lower()
          if key in COURSES_DB:
              raise HTTPException(
                  status_code=status.HTTP_409_CONFLICT,
                  detail=f"Course with code '{payload.code}' already exists."
              )
          COURSES_DB[key] = payload.dict()
          return payload

      @router.delete("/{code}", status_code=status.HTTP_204_NO_CONTENT)
      def delete_course(code: str):
          key = code.lower()
          if key not in COURSES_DB:
              raise HTTPException(status_code=status.HTTP_404_NOT_FOUND, detail="Course not found.")
          del COURSES_DB[key]
          return None

  - question: "Why should RESTful resource URIs use nouns instead of verbs (e.g. /api/courses instead of /api/getAllCourses)?"
    answer: "Because the HTTP method (GET, POST, PUT, DELETE) already represents the verb/action. Using verbs in URIs (/getAllCourses, /createCourse) results in RPC (Remote Procedure Call) architecture rather than REST."
    explanation: "Standardizing on nouns allows multiple HTTP verbs to operate cleanly on the exact same URI identifier."
  - question: "What is the difference between HTTP 401 Unauthorized and HTTP 403 Forbidden?"
    answer: "401 Unauthorized means the user has not provided valid authentication credentials (unauthenticated). 403 Forbidden means the server recognizes who the user is, but the user does not possess sufficient permissions (unauthorized access)."
    explanation: "A logged-out user receives 401; a student trying to access the admin grading panel receives 403."
  - question: "When is HTTP 409 Conflict returned?"
    answer: "When a request cannot be processed due to a conflict with the current state of the resource, such as attempting to register a username or email that already exists."
    explanation: "409 indicates that the client may be able to resolve the conflict and resubmit the request."

    answer: "The server has successfully fulfilled the request, and there is no additional content to send in the response payload body."
    explanation: "Typically returned by DELETE or PUT operations where returning the deleted object is unnecessary."

<TopicSection id="rest-architecture" title="1. RESTful Architectural Constraints & URI Design">

<KeyIdea>
A well-designed REST API identifies resources using plural nouns in hierarchical paths, keeping URIs intuitive and predictable.
</KeyIdea>

Key principles of RESTful URI design:
- **Plural nouns**: Use `/api/v1/courses` rather than `/api/v1/course`.
- **Hierarchical nesting**: Model sub-resources naturally: `/api/v1/courses/mad2/lectures/1`.
- **Query parameters for filtering**: Use query strings for searching, sorting, and pagination rather than modifying paths: `/api/v1/courses?track=app-dev&page=2`.
- **Kebab-case**: Use lowercase hyphens for multi-word paths (`/api/v1/user-profiles`).

</TopicSection>

<TopicSection id="http-verbs-idempotency" title="2. HTTP Methods, Idempotency, and Safety">

<KeyIdea>
Understanding idempotency is critical for distributed web APIs: network retries on idempotent endpoints do not alter the end state of the database.
</KeyIdea>

| HTTP Verb | CRUD | Safe? | Idempotent? | Description |
| :--- | :--- | :--- | :--- | :--- |
| `GET` | Read | Yes | Yes | Retrieve resource representation without side effects |
| `POST` | Create | No | No | Submits data to create new subordinate resource |
| `PUT` | Replace | No | Yes | Replaces entire resource with supplied body |
| `PATCH` | Modify | No | No* | Applies partial delta modification to resource |
| `DELETE` | Remove | No | Yes | Deletes resource; subsequent deletes produce same state |

*Note: While PATCH is typically idempotent in practice, the HTTP specification does not require it to be.

</TopicSection>

<TopicSection id="status-codes" title="3. Semantic HTTP Status Codes Taxonomy">

<KeyIdea>
HTTP status codes communicate the exact outcome of requests to frontend clients and API consumers.
</KeyIdea>

Status codes are divided into five categories:
- **`2xx` Success**:
  - `200 OK`: Request succeeded.
  - `201 Created`: Resource successfully created (with `Location` header).
  - `204 No Content`: Action succeeded; response body is empty.
- **`4xx` Client Error**:
  - `400 Bad Request`: Malformed syntax or invalid parameters.
  - `401 Unauthorized`: Authentication required or token missing/expired.
  - `403 Forbidden`: Authenticated user lacks permission.
  - `404 Not Found`: Resource URI does not exist.
  - `409 Conflict`: Conflict with current state (e.g. duplicate email).
  - `422 Unprocessable Entity`: Schema validation failure.
- **`5xx` Server Error**:
  - `500 Internal Server Error`: Unhandled server exception.
  - `503 Service Unavailable`: Server overloaded or undergoing maintenance.

</TopicSection>

<TopicSection id="fastapi-routes" title="4. Resource-Based Routing in FastAPI & Flask-RESTful">

<KeyIdea>
Frameworks like FastAPI and Flask-RESTful bind resource routes to controller handlers with declarative decorators and automatic serialization.
</KeyIdea>

Using FastAPI `APIRouter`:

```python
from fastapi import APIRouter

router = APIRouter(prefix="/students", tags=["students"])

@router.get("/{roll_no}")
def read_student(roll_no: str):
    return {"roll_no": roll_no, "status": "active"}
```

This modular structure keeps routers focused on specific business entities, enabling clean testing and code organization.

</TopicSection>
