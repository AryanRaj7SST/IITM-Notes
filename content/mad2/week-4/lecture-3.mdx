      from datetime import datetime, timedelta
      from typing import Optional
      from fastapi import Depends, HTTPException, status
      from fastapi.security import OAuth2PasswordBearer
      import jwt

      SECRET_KEY = "iitm_super_secret_jwt_key_do_not_hardcode_in_prod"
      ALGORITHM = "HS256"
      ACCESS_TOKEN_EXPIRE_MINUTES = 30

      oauth2_scheme = OAuth2PasswordBearer(tokenUrl="/api/v1/auth/token")

      def create_access_token(data: dict, expires_delta: Optional[timedelta] = None) -> str:
          to_encode = data.copy()
          expire = datetime.utcnow() + (expires_delta or timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES))
          to_encode.update({"exp": expire})
          return jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)

      def decode_access_token(token: str = Depends(oauth2_scheme)) -> dict:
          try:
              payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
              return payload
          except jwt.ExpiredSignatureError:
              raise HTTPException(
                  status_code=status.HTTP_401_UNAUTHORIZED,
                  detail="Token has expired. Please refresh session."
              )
          except jwt.PyJWTError:
              raise HTTPException(
                  status_code=status.HTTP_401_UNAUTHORIZED,
                  detail="Could not validate credentials."
              )

      # RBAC Role Gate
      def require_role(required_role: str):
          def role_checker(claims: dict = Depends(decode_access_token)):
              user_role = claims.get("role")
              if user_role != required_role and user_role != "admin":
                  raise HTTPException(
                      status_code=status.HTTP_403_FORBIDDEN,
                      detail=f"Operation requires '{required_role}' privileges."
                  )
              return claims
          return role_checker

<TopicSection id="sessions-vs-tokens" title="1. Stateful Session Cookies vs Stateless JWTs">

<KeyIdea>
Stateful sessions store user data in server memory or Redis; stateless tokens store authenticated claims inside a tamper-proof cryptographically signed string.
</KeyIdea>

In session-based authentication:
- Server stores session: `session_id_123 -> { user: "alice", role: "student" }`.
- When scale reaches 50 server instances, every request must query a shared session cache (like Redis).

In token-based authentication (JWT):
- The token itself contains the user ID, role, and expiration date.
- Any server with the secret verification key can validate authenticity locally without a database round-trip.

</TopicSection>

<TopicSection id="jwt-anatomy" title="2. Anatomy of a JWT: Header, Payload, and Signature">

<KeyIdea>
A JWT consists of three parts concatenated by periods (`.`): Header, Payload, and Signature.
</KeyIdea>

$$\text{JWT} = \underbrace{\text{Base64URL}(\text{Header})}_{\text{Algorithm \& Type}} \quad.\quad \underbrace{\text{Base64URL}(\text{Payload})}_{\text{Claims: user\_id, role, exp}} \quad.\quad \underbrace{\text{HMAC-SHA256}(\text{Header} + \text{Payload}, \text{Secret})}_{\text{Cryptographic Signature}}$$

1. **Header**: Declares the token type (`JWT`) and signing algorithm (`HS256` or `RS256`).
2. **Payload**: Stores claims:
   - Registered claims: `sub` (subject), `exp` (expiration), `iat` (issued at).
   - Custom claims: `role: "ta"`, `course: "mad2"`.
3. **Signature**: Prevents tampering. If an attacker modifies `role: "student"` to `role: "admin"` in the payload, the signature check fails immediately.

</TopicSection>

<TopicSection id="refresh-tokens" title="3. Access Tokens vs Refresh Token Rotation">

<KeyIdea>
Separating short-lived access tokens from long-lived refresh tokens balances convenience against security exposure.
</KeyIdea>

- **Access Token**: Short lifespan (10–30 minutes). Transmitted with every API call. If intercepted, the attacker's window of opportunity is limited.
- **Refresh Token**: Long lifespan (7–30 days). Stored securely (in an `HttpOnly`, `SameSite=Strict` cookie). Used exclusively at `/auth/refresh` to obtain a fresh access token.

When implementing **Refresh Token Rotation**, issuing a new access token invalidates the old refresh token, rendering stolen tokens single-use and easily detectable.

</TopicSection>

<TopicSection id="rbac-protected-routes" title="4. Role-Based Access Control (RBAC) in FastAPI">

<KeyIdea>
Declarative authorization guards protect sensitive administrative endpoints by validating user roles before executing route handlers.
</KeyIdea>

```python
@router.post("/grades", dependencies=[Depends(require_role("instructor"))])
def submit_exam_grades(grades: GradePayload):
    # Only instructors or admins can reach this function
    return {"message": "Grades submitted successfully."}
```

This declarative dependency approach ensures consistent authorization enforcement across all API endpoints.

</TopicSection>
