</KeyIdea>

<TopicSection id="html-invocation" title="2. Front-End JavaScript Runs From an HTML Page">

<KeyIdea>
Front-end JavaScript must be invoked as a script from an HTML page, and is loosely structured like Python.
</KeyIdea>

- For basic front-end use you do not write a program and run it directly. JavaScript is invoked as a script from an HTML page, and only then does it have a document associated with it.
- Front-end JavaScript is closely tied to the DOM (Document Object Model). If it is not invoked from an HTML page there is no document, so it cannot do anything useful.
- It is a **scripting language with no compilation step**: what you type is what runs, as in Python.
- It is **loosely structured**, like Python. C is more structured: `#include` lines (usually at the top), then a main function (`int main`) with open and close braces and a sequence of statements inside.
- A Python script can be a bunch of statements executed one after another. In this sense JavaScript is closer to Python than to C.

<AddedByTutor>
Modern JavaScript engines compile code internally for speed (just-in-time compilation). What the lecture means is that there is no separate compile step that you run yourself.
</AddedByTutor>

</TopicSection>

<TopicSection id="reserved-words" title="3. Identifiers and Reserved Words">

<KeyIdea>
Know the reserved words, and never use one, or a word you suspect is special, as a variable name.
</KeyIdea>

- **Identifiers** are the words used in the language. You need to be aware of them but need not memorise the list.
- There are a number of **reserved words**. Examples from the lecture, with Python comparisons:

| Word | Meaning | Python comparison |
| :--- | :--- | :--- |
| `if` | Conditional (an obvious reserved word) | Same idea |
| `function` | Defines a new function | Equivalent of `def` |
| `let`, `const` | Declare variables (covered later) | No direct equivalent |
| `while` | Implements while loops | Same idea |
| `with` | Exists in both languages | Slightly different meaning in JavaScript |

- It is not a one-to-one translation of everything seen in Python.
- Key rule: if something is a reserved word, do not use it as a variable name.
- Good general advice: avoid any name you even suspect is used by the language. Do not call a variable `delete` or `del`. `del` is not a reserved word here, but it could be used for something you do not know about.
- If in doubt, modify the name slightly so it is unlikely to be reserved. You can always choose another name.

<AddedByTutor>
In JavaScript, `with` is a statement that adds an object to the scope chain. It is discouraged and not allowed in strict mode. `delete` is an operator and is a reserved word.
</AddedByTutor>

</TopicSection>

<TopicSection id="literals-avoid" title="4. Literals and Other Words to Avoid">

<KeyIdea>
true, false and null are literal values; a few more words should be avoided even though the language does not forbid them.
</KeyIdea>

- **Literals** include `true`, `false` and `null`.
- `null` appears a lot in JavaScript. It is the equivalent of `None` in Python, "sort of the undefined state" in the lecturer's words.
- Literals are not keywords in the sense of starting or ending a statement. They are values used in comparisons and assignments.
- Other words to avoid: `package`, `private`, `public`, `undefined`, `async`. You will see them later in code.
- It says "avoid" rather than "forbidden" because in principle the language does not stop you from redefining these words with different meanings. It is better to avoid them than rely on a ban.

<CheckBadge reason="Transcript describes null as 'the undefined state'. In JavaScript, null (an intentional empty value) and undefined (a value not set) are different; both are covered in section 6." />

<AddedByTutor>
Strictly, `package`, `private` and `public` are reserved only in strict mode, while `undefined` is a global property and `async` is a contextual keyword. The advice to avoid all five still holds.
</AddedByTutor>

</TopicSection>

<TopicSection id="statements-expressions" title="5. Statements and Expressions">

<KeyIdea>
A statement is executed; an expression is evaluated to a value and can be used wherever a value is needed.
</KeyIdea>

- The language can be seen broadly as **statements** and **expressions**.
- **Statement:** a piece of code that can be executed. Example: `if (something) { do something }`, with the body in the curly brackets. It can be a standalone operation or have side effects.
- **Side effect:** for example `console.log`, which prints something in the console but does not directly affect any variables or data in the program.
- **Expression:** something executed to obtain a value that is returned. Example: `x = 10` takes the value 10 and assigns it to `x`, and there is a value being returned.
- Even a bare `"Hello world"` is an expression: it is a value that can be used anywhere a value is needed, and it returns itself.
- Function arguments must be expressions. For a function `add(x, y)`, `x` and `y` must evaluate to values. An `if` statement cannot be an argument because it does not return a value to pass into the function.

<CheckBadge reason="At the end of the demo the lecturer calls console.log a statement with no return value. In JavaScript, console.log(...) is a call expression that returns undefined (shown in the tested demo, section 11). It is used as a statement for its side effect." />

</TopicSection>

<TopicSection id="primitive-types" title="6. Primitive Data Types">

<KeyIdea>
There is one number type, plus bigint, string and Boolean; undefined and null are special non-values.
</KeyIdea>

- Primitive types are built into the language.
- `undefined` and `null` are important to keep in mind but, in the lecturer's words, are "not really data types". They are special cases called **non-values**.
- The primitive types listed:

| Type | Notes |
| :--- | :--- |
| Boolean | `true`, `false` |
| `number` | No separate `int` and `float`, unlike C |
| `bigint` | Stores large integers |
| `string` | Stores and manipulates text |

- Comparison: Python itself does not distinguish `int` and `float` in the same way the question arises, but NumPy distinguishes `int`, `float32` and `float64`. JavaScript natively calls everything a `number`.

<CheckBadge reason="Transcript says undefined and null are not really data types. The ECMAScript specification lists Undefined and Null as primitive types (together with Symbol, which the lecture does not mention) [check: confirm which convention the course uses]." />

</TopicSection>

<TopicSection id="objects-functions" title="7. Objects and Functions as Values">

<KeyIdea>
An object is compound data; functions can be assigned to variables and stored inside objects.
</KeyIdea>

- **Object:** a compound piece of data with multiple things put together inside it. Objects need more time later because they are the basis of how classes are implemented in JavaScript.
- **Function:** for example `add(x, y)` takes two arguments and returns a value.
- A function can be handled like an object. You can take a function name, assign it to a variable, and use the variable as the function. This is possible in Python too but is used more in JavaScript.
- A common pattern: define a function as an **anonymous** object and assign it to a variable.
- Objects can themselves have functions inside them. In object-oriented terms this is a **method** of the object or class.
- In JavaScript, "a function can have an object associated with it".

</TopicSection>

<TopicSection id="syntax-demo" title="11. Syntax Demo (Tutor Addition)">

<KeyIdea>
A short script that shows expressions, primitive types, functions as values and objects with methods.
</KeyIdea>

<AddedByTutor>
Everything in this topic is added by the tutor. The script was run with Node.js v22, and the output below is real. It was not run in Replit or a browser. Because it uses strict mode, it declares `x` with `let`. The lecture's `x = 10` without a declaration would be an error in strict mode.
</AddedByTutor>

```javascript
// my-repl/demo.js
"use strict";

// expression: produces a value
let x = 10;
console.log(x);
console.log("Hello world");

// function arguments must be expressions
function add(a, b) {
  return a + b;
}
console.log(add(x, 5));

// non-values and primitive types
let nothing = null;
let notSet;
console.log(nothing, notSet);
console.log(typeof 42, typeof 3.14, typeof 10n, typeof "text", typeof true);

// functions are values
const addAgain = function (a, b) {
  return a + b;
};
console.log(addAgain(2, 3));

// an object can hold a function (a method)
const calc = {
  name: "calc",
  add: addAgain
};
console.log(calc.add(4, 6));

// console.log is a call expression that returns undefined
console.log(console.log("side effect"));
```

### What Each Part Does:
- **Lines 4-6**: an assignment is an expression with a value, and a bare string is also an expression.
- **Lines 9-12**: a function whose arguments `x` and `5` are expressions.
- **Lines 15-18**: `null` and `undefined` as non-values; `typeof` shows that `42` and `3.14` are both `number`, and `10n` is `bigint`.
- **Lines 21-24**: an anonymous function stored in a variable, then called through it.
- **Lines 27-31**: an object holding a function (a method).
- **Line 34**: the inner call prints and returns `undefined`, which the outer call prints.

#### Expected Execution Output:
```
10
Hello world
15
null undefined
number number bigint string boolean
5
10
side effect
undefined
```
